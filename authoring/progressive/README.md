# Source-backed progressive schemas

This directory is generated from the runtime's schema-source modules. Start with [the small category index](index.json), choose a category, then read its complete module task pack. Each pack puts the selected structural schema, semantic contract closure and original complete examples together. Category component entries point directly to their exact schema signatures inside the pack. They are navigation aids, not a substitute for the pack's constraints. Audit manifests are separate from the model-facing task body.

## Two delivery paths, one schema source

- Agents with file access read only the selected category and module packs. Module selection includes declared shared dependencies and reports every node type it brings in.
- Web Chat can use [the complete single-file schema](webchat/iui.schema.json). It is generated by the runtime's `--full` command from the same source modules and the explicitly remaining legacy source. It is byte-identical to that source revision's canonical schema.

The catalog migrates 83 of 218 registered node types into sixteen source modules. The other 135 types are explicitly listed in [the legacy index](legacy-components.json). The foundational layout family still brings in 41 types; this is module-level selection, not an assertion that every component has already been split into its own file. The 212/256 historical functionality count is unrelated to this migration count.

The full Web Chat schema is an output, never an additional manual maintenance source. The old [Web Chat guide](../../WEB-CHAT-GUIDE.md) remains a versioned compatibility reference. Generated files must not be edited by hand.

## Generate from a fixed source checkout

The verified public source is [e6d93b0](https://github.com/Micraow/Inform-UI/commit/e6d93b0b1640fe6955f33acdb23f565d6d406675). [The publication receipt](source-public.json) compares 119 relevant local files to that immutable remote tree. Check out that public commit and install its declared dependencies. For a fresh generation, use its full public SHA as the revision:

```sh
node scripts/generate-progressive-catalog.mjs \
  --library /path/to/Inform-UI \
  --revision e6d93b0b1640fe6955f33acdb23f565d6d406675 \
  --output authoring/progressive
```

The checked-in artifacts retain their original local source proof f92e91f3, plus the independently verified public commit. To reproduce that exact proof checkout, the generator accepts an explicit `--publication source-public.json` receipt and rechecks its file hashes; a fresh public checkout records the public commit as its own source revision.

For a cross-module task, request actual component types. The adapter uses the runtime's stable module CLI, not a second schema implementation:

```sh
node scripts/progressive-source-consumer.mjs \
  --library /path/to/Inform-UI \
  --revision e6d93b0b1640fe6955f33acdb23f565d6d406675 \
  --components text,input,questionnaire \
  --root document --output task.json
```

Unknown or unmigrated component requests fail explicitly. There is no silent fallback to the large schema. Select the full contract deliberately when the task needs an unmigrated type. Selected Node unions are narrowed to the actual module closure; every other selected definition must match the full schema exactly.

## Semantic and version boundaries

All sixteen modules declare explicit semanticContractPaths. The adapter includes these required sections and complete examples; ordinary Markdown links remain navigation rather than automatically importing release notes, CDN guides or unrelated contracts. Older source indexes without this field retain their local transitive-link behavior. External source links are never fetched. Example documents must validate within their actual selected schema, including the Document envelope and state where requested. A complete document still needs same-version `validateDocument`, because bindings, ownership, conditions and other runtime semantic constraints are more than JSON Schema.

Preserve missing, null, invalid, zero and false separately. Questionnaire hidden drafts follow an explicit retain/clear policy and never enter submitted answers or computations while hidden. Invalid or required-unknown active input suppresses results. Read the full nearby questionnaire contract for pending validation, frozen snapshots, cancellation and stale asynchronous completions.

The generated source metadata distinguishes local source identity from verified public publication. A null public commit means a public installation instruction cannot yet rely on that source. The existing214 CDN has its own fixed assets and does not gain new source tooling or Questionnaire support through this documentation update.

Generation measurements are UTF-8 bytes. This architecture has not itself been evaluated for model generation accuracy or token counts. The earlier [eight-task pilot](../pilot-v1/METHOD.md) tested different fixed entry materials and remains separate evidence.
