# 进度、占位与来源：作者负责的真实性边界

本文件匹配66节点固定资产d370。实际CDN字节已核验，核心集中CI338项Node、241项Chromium及42旧＋18新消费者通过；旧62节点资产01ae不含这四项，不能混用。

## 场景选择

- 有明确来源的已完成比例：loading.progress。只提供实际已知的有限0–100数值，不估计时间、不模拟自动增长。
- 真实任务正在进行但比例未知：省略progress，并给清楚label。未知不能用0替代；0代表已知零进度。
- 只想说明未来内容的结构：loading-block。标签必须可读；形状不会自己下载或变成实际文章/头像。
- 解释旁的一项来源：citation。作者已核实资料和相关性后，提供准确title/url与需要的publisher/description。
- 几份延伸阅读：web-link-cards。作者顺序、重复项和字面内容保留；不会搜索、去重、排名或给出可靠性判断。
- 页面不需要交互时：正文、普通link或直接说明未知值即可。不为了让页面显得忙碌而加旋转图形。

精确字段、默认值和范围保留在根SKILL与完整指南。所有来源字段为字面值，只有loading.progress使用普通Value表达式；不要对来源记录猜bind、state、URL模板或自动摘要字段。

## 两种数值约束不能混用

form数字字段的min/max/step决定用户草稿与提交是否有效，并不单独限制宿主全局state。宿主明确赋值仍须满足整个文档所有真实语义约束。

loading.progress要求解析后为有限数值0–100，这是全局约束。因此某个form单纯允许宿主写入5，不意味着引用它计算出的125%也可以提交。整个setState会原子拒绝，旧state、DOM和焦点保留；不裁成100、不部分更新其他指标。分母为0、数值字符串、null和非法引用也应先拒绝。

supplied-source-reading.json只用form字段，没有slider全局范围来掩盖这个边界：初始1/4为25%，合法写2为50%；用户键入5留数字草稿，宿主明确写5因计算125%被loading语义拒绝。默认文本字段仍即时绑定；这个数字示例不能泛化为所有输入都保留最后有效值。

## 读取和状态生命周期

1. 初次挂载：loading显示所给比例或明确未知；占位呈现确定的有限形状；来源按作者顺序显示。没有后台任务或来源请求。
2. 合法setState：只刷新有绑定的数值。loading的progressbar元素保持；来源列表DOM、已有焦点和局部滚动保持，资料链接没有自动“已读”状态。
3. 来源分页：原生按钮按当前栏宽瞬时滚动。边界按钮仍可聚焦、带aria-disabled，Enter/Space/真实点击无操作；不是disabled导致焦点消失。非live范围提示包含部分可见条目，不是选中项。
4. 来源点击：用户原生链接操作才打开新标签页；新窗口不取得opener，页面不发送来源referrer。组件不会因此增加进度、记住访问或确认读过内容。
5. 更换文字/URL/shape：由宿主update整份合法文档。成功替换会重置其他组件局部状态；不要通过频繁update模拟进度或破坏用户阅读位置。非法更新先原子拒绝。
6. dispose：清理绑定、来源滚动/尺寸/字体监听与等待帧；不是取消未由组件发起的外部任务。

## 作者检查清单

- 比例的来源和单位清楚；区分缺省、0、小数与100，不把原始浮点数承诺为额外舍入。
- 源标题、作者摘要与真实URL一致；hostname与publisher是不同信息，不给虚构链接伪造真实出版物身份。
- 编号是作者提供的，不暗示自动脚注映射、引用次数或质量排名。
- 关键解释保留正文；横向资料列表只是补充，不让来源摘要承担未经核实的主结论。
- 键盘、触屏、减少动态效果、窄屏/长标签和RTL分别检查；自动断言不等于全面无障碍合规。
